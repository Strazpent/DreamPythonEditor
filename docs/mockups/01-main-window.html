1Run split button. ▶ Run · Session ▾ always shows the namespace mode. Ctrl+Enter runs the selection, or the buffer if nothing is selected; Ctrl+Shift+Enter the buffer; Ctrl+Alt+Shift+Enter the cell. The ▾ menu holds Run selection, Run buffer, Run file, Run line and advance, Run in / without transaction and the mode: Session or Isolated. Stop is Esc or Shift+F5 while a run is active.
2One undo step per run. Each run is one editor transaction named Dream: <tab> #N. Undo Last Run (Ctrl+Alt+Z, only inside Dream) reverts its recorded edits; imports, asset renames and moves and PIE edits are never undoable, and the run block says so; file writes are never undoable either (RUN-07); a run that renames assets also clears the editor's undo history, as Run #14 did; Ctrl+Z in a buffer is always text undo. Run File defaults to no transaction.
3Explorer. Project scripts, a read-only studio library, journaled untitled buffers and Recent. Problem counts appear on each file. Dream itself ships no init_unreal.py; the one listed belongs to the project.
4Cells and run marks. Each # %% header shows its last run's number, time and duration, here #13 · ran 12:40 · 0.03 s and #14 · ran 12:41 · 0.42 s · error (RUN-03). After a run, the gutter's run lane, between the line numbers and the change bars, marks each statement by how it ended (EDT-18): a solid green bar for ok, a dashed red bar for the statement that raised (lines 9–14), a dotted amber bar for one that was stopped, and a dash-dot blue bar for one that ended the run through SystemExit (bar patterns proposed); only ok lines are tinted. A run replaces only the marks on its own statements' lines, so the trail stays: lines 2–5 still carry Run #13's marks after Run #14 marked line 8, and each tooltip names its run and outcome (“Ran in #13 · ok”). Line 17 was not reached and stays unmarked; line 15 was typed after the run, and an edited line loses its mark.
5Change bars. The outlined bars at the gutter's right edge mark lines added (green) or modified (blue) since the last save; line 15 was added after Run #14. The run marks are filled or patterned and have their own lane to the left, so a change bar never reads as a run mark. Merged completion, quick docs and hover are in mockup 03.
6Inline inspections. Ruff, the language server and dream-check (SUM codes) show squiggles as you type, without running code.
7Structured output. Every run, REPL lines included, gets a number, source, time and outcome (ok, error, cancelled, not executed, lost) and its undo name. An error keeps its transaction; the header offers Undo this run unless the run renamed assets. Traceback links open the line; F4 walks them. The uncaught exception also becomes a runtime error in Problems at line 14.
8REPL prompt. Enter runs when the input is complete, Shift+Enter adds a line, Up walks history. It runs in the Session. The output area, on top by default, holds the Output, REPL and Problems tabs (F8 walks Problems) and the prompt strip under the tab body, so the prompt sits between the history and the code, as in Maya. View ▸ Output Position moves the area below the code.
9Variables. The Session is the Unreal console's globals, shared with the Output Log Python console. Values expand lazily and are never read through property getters. The last result is bound to _.
10Selection aliases. sel, sel_assets, world and subsys(cls) are refreshed while idle. Once your code rebinds one of these names, Dream leaves it alone for the rest of the session, and its row and hover then read “sel: your value since Run #N; no longer refreshed”.
11Status bar. Run state (Idle, Starting, Running, Stopping…, Task running; Paused shows only in the Paused window, since the tab is not drawn while it is open), the namespace mode, interpreter, language-service health, cursor and journal age.
12Dream in the Unreal status bar. Mark · state · detail · [Stop]. It stays visible when the Dream tab is hidden. After an error it reads Dream · Run #N error and a click opens the traceback; Dream · Run #N cancelled and Dream · Run #N not executed open the run block.
13Input echo. Each statement is echoed with › and its line number just before it runs, so its output follows directly under it and the block reads as a history of what ran: in Run #13 the printed line sits between the echo of line 4 and the echo of line 5 (OUT-12). REPL runs echo with >>> and .... Normal folds a statement's echo after 6 lines; Echo input in the toolbar hides echo lines. The Output Log gets the output, not the echo.
14Run line and advance. Alt+Enter runs the line or statement under the caret, then moves the caret to the next statement, so repeated presses walk the buffer one statement at a time, each a numbered run (RUN-26). On a for or with header it runs the whole block; stepping through a body skips its else or except clause, so nothing runs twice. Until you first use the key, the hint chip shows at the end of the caret line when it starts a statement and you are not typing (proposed).
