"""Asset naming rules for studio_tools."""
import unreal
PREFIXES = {
"StaticMesh": "SM_",
"SkeletalMesh": "SK_",
"Texture2D": "T_",
"MaterialInstanceConstant": "MI_",
"NiagaraSystem": "NS_",
}
def asset_name(data: unreal.AssetData) -> str:
cls = str(data.asset_class_path.asset_name)
name = str(data.asset_name)
prefix = PREFIXES.get(cls, "")
return name if name.startswith(prefix) else prefix + name

1Reload on save is opt-in. Deep reload is manual by default (Reload Package). This dev root has opted in, so saving naming.py reloads its package and a notification gives the result even when Output is hidden.
2Entry point, Ctrl+F5. The tab binds studio_tools.ui.main; Ctrl+F5 reloads its package and then calls it, so trying a change is one key. F5 stays Debug.
3Reload report. An output block, numbered like any run, lists each module in dependency order (parent packages first, then the saved module, then its importers), why it reloaded, which __dream_unload__() hooks ran, and the time per step. unreal, the stdlib, site-packages, the engine's Content/Python and dream_editor are never reloaded.
4Stale callbacks. Old functions still registered with Slate keep running pre-reload code and pile up with each reload. The report names them and offers to insert an unload hook that unregisters them.
5Stale Session names, meaning names bound to objects from reloaded modules, are listed by name. Reset session clears the Session back to its first-capture keys; Show holders lists what still refers to the old objects.
6Interpreter. Python version, executable, isolation, Developer Mode and restrictive mode, read live from sys and the plugin settings.
7sys.path with origins. Every entry in import order, badged engine, project, plugin, UE_PYTHONPATH or user, so you can see why a module resolves where it does. Shadowed modules are flagged.
8Startup scripts. The third-party init_unreal.py files found on sys.path, in run order, with their result from this session's log. Dream ships none of its own.
9Environment doctor. Interpreter and version, sys.path duplicates and shadowing, startup-script failures, wrong ABI tags, PYTHONPATH and UE_PYTHONPATH, Developer and restrictive mode, language-server binaries and hashes, stubs, the journal folder and the policy. Dream never changes an engine setting itself; Open setting links to it.
10Effective policy. The doctor names each policy layer it read: machine %ProgramData%\DreamPythonEditor\Policy.json, studio DREAM_POLICY_PATH, project <Project>/Config/Dream/Policy.json. The machine file counts only when it is owned by Administrators, SYSTEM or TrustedInstaller; otherwise the doctor names the file and its owner. Inspector opens Settings at the layer that set each value.
