1Drag assets into code. The drag label says what the drop will insert: unreal.load_asset("/Game/Path/Asset.Asset") for each asset. Holding Alt inserts the soft object path as a string instead.
2A multi-selection becomes a list. Three assets drop as a list of three load calls, tinted until the next edit. It is one ordinary edit, so Ctrl+Z in the buffer removes it.
3Ctrl+Shift+V inserts the sel = …get_selected_level_actors() line at the caret. It is your own assignment, so the alias rule treats sel as yours from then on, and Variables and the hover then show “sel: your value since Run #N; no longer refreshed”.
4Selection aliases. sel, sel_assets, world and subsys(cls) are written into the Session only while idle, and only if the name is absent or still holds what Dream wrote. Hover says “selection as of” a time.
5Actors as code. An actor drops or copies as unreal.find_object(None, "<full object path>") # <label>, never as a label lookup, so it resolves to the same object as sel[2].
6One Dream submenu. The actor and asset context menus each get a single Dream submenu: Copy as Python, Insert into Dream, and Run on selection ▸ with the shelf items that accept this selection.
7Run on selection. Each shelf item shows its tier. It runs Isolated with sel (or sel_assets) bound in its fresh namespace, as one undo step named after the item.
8Copy as Python and Insert into Dream. Both produce the same code; Insert puts it at the caret of the active Dream buffer. Several actors become a list of find_object calls, one per line, each commented with its label, sanitised to one line of at most 80 characters.
9Details property. Copy as Python on a property row gives text that runs on its own: obj = unreal.find_object(None, "<path>") # <label>, then the set_editor_property line with the current value as a literal, then the getter as a comment.
10Tools ▸ Dream Python Editor opens the tab (mirrored under Window). Tools also lists Dream Shelf and the shelf items registered for the Tools menu.
11Status-bar patterns. Mark · state · detail · [Stop]: Running 41 s · Run #22 · 312 / 1,204, Task running · 40 / 300, Run #23 error (a click opens the tab at the traceback), Run #24 not executed and Run #25 cancelled (a click opens the run block), and Idle with the last result. The Running pattern is live only in Live (docked) Preview; during a Run-window run the item keeps its last painted text.
12Visible with the tab closed. The item is painted whenever the editor paints, so it reports shelf and menu runs even when the Dream tab is not open.
